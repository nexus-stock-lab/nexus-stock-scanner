# NEXUS 米国株・仮想30トレード検証

実売買・注文・口座照会・X投稿・外部通知の送信機能はありません。
mainへの反映は所有者の確認待ちです。運用台帳は現在0件です。

## 承認済みルール

2026-10-27に所有者が承認した規約を `strategy_rules.py` に実装しました。

- 区分は「反発確認」「反発初動」。scanner.pyの抽出式とreview.pyの二次調査条件は維持。
- 正式判定は日本時間23:45。直前60秒以内の最終有効SIP取引を仮想基準価格とし、翌0:01以降に照合。
- 最新四半期の売上前年同期比が正、かつ営業利益が黒字または前年同期より改善。
- 会社の売上見通しが下方修正されていないこと、下落理由・重大な事業毀損の確認には公式根拠が必要。
- 正式な決算予定の3米国営業日前から発表当日まで新規登録しない。予定不明も保留。
- 損切りは直前20完了営業日の安値、目標は直前60完了営業日の高値。判定価格でR:R最低1.5を再検証。
- 累計30件。保有中の同一銘柄への重複登録を禁止。
- 損切り・利確・業績悪化・90日満了で決済。閉場中の満了は満了後最初の通常取引時間の有効取引を使用。

判定・市場取引・取得照合・実際の登録処理の時刻は分けて保存します。
価格は仮想基準であり、市場注文が実際に約定できた証明ではありません。手数料・スリッページは未モデル化です。

## 実装した処理

1. `scanner.py` は全市場を広く調査し、使用した完了日足も保存します。現在NY日付の未完了日足は除外。
2. `official_data.py` はSECの受理日時を照合して、最新の比較可能な四半期売上・営業利益を取得。年次の第4四半期は通期から9か月を差し引きます。半年累計を四半期として扱いません。曖昧な訂正値や、より新しい未突合決算発表は保留。
3. 最新の公式SEC書類と決算資料99.1を自動収集し、本文・取得日時・公表日時・ハッシュを保存します。
4. `daily_runner.py` は判定前の候補を日付別に固定し、根拠付き正式計画を準備。遅れて作った計画から過去の約定を作りません。
5. `market_provider.py` はAlpaca Market DataのGETだけでSIP取引を取得。全ページ、約定条件、取消・訂正状態、米国取引時間を確認します。
6. `paper_engine.py` は登録・損切り・利確・業績悪化撤退・90日決済・区分別勝率と期待値R等を計算します。
7. 保有履歴を5分区間で読み、追跡を再開可能なカーソルで保存。予算超過・データ欠落・未調整企業行動は見える形で保留します。
8. 業績悪化の撤退確認は保有開始後の最初の確認を保存し、古い見通しレビューで上書きしません。公式根拠付きの重大な事業毀損も対象です。根拠の破損・未来日時は保留し、確認状態をiPhone向けSummaryへ表示します。

参照価格の取得前には、登録対象銘柄について企業行動データを利用できることも確認します。

## 自動化の限界（重要）

**公式資料の収集と数値判定は自動化していますが、会社見通し・下落理由を自然言語から判定する処理は未実装です。**
「悪材料のキーワードがない」「売上が伸びた」だけで事業リスクを合格にしません。

根拠を確認したレビューは `input/official_reviews.json` に日付・銘柄ごとに記録し、
`input/official_documents/<sha256>.json` の公式本文・公表日時・取得日時・引用と照合します。
現時点ではこのレビューを自動生成する仕組みはありません。レビューがない銘柄は正式計画を作らず、理由をSummaryへ出します。
このため、**完全放置で30トレードが自動的に集まる状態にはまだなっていません。**

分割、配当、銘柄変更などの企業行動については自動検知して停止します。
株数・価格・配当金の自動調整は未実装なので、未調整のまま損益を確定しません。
取引先の訂正や企業行動通知が後日届く可能性もあります。確認できない90日期限超過はOPENのまま警告します。
過去の撤退確認を、すでに追跡済みの期間に後から追加した場合は、履歴の再突合が必要として停止します。過去の正確な最初の取引を検証せず、後の価格で決済したことにはしません。この再突合の自動復旧は未実装です。

## iPhoneでの確認

GitHub → Actions → NEXUS Market Scan → Summary。
通常は登録数・保有数・決済数・勝率・期待値R・候補が止まった理由を見るだけです。
手動実行では `prepare / finalize / reconcile / track` を選びます。

main反映後の予定:

|日本時間|処理|
|---|---|
|平日18:00|全市場調査、SEC数値と公式資料収集、候補保存|
|平日23:35|確認済みの根拠から正式計画を保存|
|翌0:05|23:45時点の履歴照合、条件がそろった計画だけ仮想登録|
|翌0:35〜6:35・毎時|保有の価格履歴追跡と業績悪化監視|

GitHubの開始遅延はあり得ます。判定時刻は23:45から変更しません。
スケジュールはmainに入るまで動きません。GitHubアカウント側の既存通知設定は変更しません。

## 保存と検証

- 台帳: `input/trades.csv`
- 計画と約定根拠: `input/evidence.json` / `input/plans/`
- 判定前候補: `input/research/`
- 公式数値・文書: `input/official_evidence/` / `input/official_documents/`
- 価格・企業行動の根拠: `input/market_evidence/`

判定用60秒の生データ、決済に使った正確な取引、履歴の照会範囲・件数・全応答ハッシュを保存します。
大量の非決済取引すべてはgitへ保存しません。後日同じAPIを照会しても訂正で変わる場合があるため、
ハッシュだけから当時の全取引を完全再現できる保証はありません。
台帳と根拠は同じブランチの同じコミットに保存し、競合時にforce pushしません。

`python -m unittest discover -s tests -v`

単体・通しテストの架空トレードは一時フォルダ内だけで実行します。
`integration_probe.py` は実データの取得・正規化だけを検証し、台帳へ一切登録しません。

認証付きSIP取得run 40377918991で、AAPLの2026-10-26 23:44～23:45 JSTの2,110件を取得済みです。
本番エントリー～決済の実績はまだありません。テスト成功と運用実績は区別します。

## 接続

AlpacaのPaper用キーをGitHub Actions Secrets `ALPACA_DATA_KEY` / `ALPACA_DATA_SECRET` に保存。
キーをソース・チャット・スクリーンショットへ載せないでください。
SECへの取得要求に提示するアプリ名と連絡先メールを、ActionsのRepository Secret `NEXUS_SEC_USER_AGENT` に保存してください。
値は `NEXUS 実際の連絡先メールアドレス` の形式です。メールはこのリポジトリのコードやチャットへ貼りません。GitHubのSecretを優先し、従来の同名Variableも読み取れますが、連絡先をログで隠すためSecretを推奨します。
空欄・メール形式なし・改行を含む値ならSECへの要求を止め、未設定として保留します。設定だけでSEC接続成功を保証しません。
接続診断はSECの失敗先とHTTPステータスを公開URLの範囲で記録し、認証情報は出力しません。
アクセス拒否・未取得は保留し、有料契約・新たな課金設定は行いません。
